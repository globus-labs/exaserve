# Hardening and release utilities

This directory contains offline validation and release-evidence utilities. It
does **not** contain a deployment launcher. Production lifecycle ownership is
entirely in the typed Python composition root and supervisors described in
`doc/PRODUCTION_HARDENING_EXECUTION_PLAN.md`.

## Intentional shell boundary

`run_hermetic_check.sh` is a developer/CI command wrapper. It selects a Python
executable, sets a deliberately restricted test environment, and replaces
itself only with bounded test commands. It does not submit jobs, construct a
runtime plan, launch Ray or a gateway, inspect logs for readiness, publish
state, or own cleanup. Keeping this small wrapper is an operator convenience,
not a second control plane.

The other repository shell files under `scripts/` are opt-in dependency
build/install helpers for HAProxy, NGINX, Pingora, and Envoy. They never run on
the deployment path. Downloading helpers require an operator-supplied audited
SHA-256 and fail closed if it is missing or mismatched. The Pingora helper does
not bootstrap Rust and refuses to build without a committed lockfile. HAProxy
is the production gateway target; the other gateways remain
validation/benchmark-only unless the support matrix is amended and their
qualification gates pass.

Scheduler batch text is an unavoidable site boundary, but it is generated by
the shared scheduler backend from a canonical persisted plan using quoted,
typed fields. The rendered batch script performs site setup and one final
Python entry-point invocation; it is not a hand-maintained lifecycle script.

Historical run directories under `artifacts/`, `run_logs/`, `tmp/`, and stale
local `build/` trees may contain copies of the retired shell implementation.
Those files are evidence or disposable build output, not package input. The
release builder starts from current source, rejects retired paths, and verifies
the built archive before publication. They must not be cited as reachable
production code.

## Utilities

- `build_release_artifacts.py`: stage an allowlisted clean source input, then
  build and verify immutable sdist/wheel outputs. Ignored checkout egg-info and
  build caches are never inputs; both the sdist surface and wheel package bytes
  are audited before publication.
  Isolated dependency installation is the default. When an external package
  index is unavailable, `--verified-local-tools` is the only offline fallback;
  it fails unless the interpreter has the exact pinned build-tool versions and
  no undeclared setuptools/distutils backend plugins, then records the tools,
  backend entry points, Python executable hash, and `pyproject.toml` hash in the
  artifact manifest.
- `run_final_null_qualification.py`: execute the declared final qualification
  protocol inside a validated compute allocation.
- `run_packaged_gate.sh`: test-only Aurora wrapper for installing an immutable
  wheel in a fresh virtual environment and running the full installed-package,
  resource, and typed-core gates. It has no deployment lifecycle role.
- `validate_findings.py`: enforce the canonical finding-ledger schema.
- `adjudicate.py`: ledger-maintenance helper; it cannot manufacture approval or
  convert missing evidence into closure.
- `run_hermetic_check.sh`: clean-dependency and randomized-order test wrapper.

Deleted spike/battery scripts were migration experiments. Their retained logs
remain historical evidence, but they are not release gates and must not be
restored into the package.
